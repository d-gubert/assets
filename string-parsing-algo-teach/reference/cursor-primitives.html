Cursor Primitives

The complete toolkit for hand-written parsing. Everything else in this workspace is built from these.

State

const src = "…";   // immutable input
let   pos = 0;     // the only mutable state in the whole parser

The three primitives

peek()

Returns the character at pos. Does not move. Returns a sentinel ("\0") past the end so loop conditions terminate on their own.

advance()

Returns the character at pos and increments pos. The only thing in the system that moves forward.

atEnd()

pos >= src.length. Guards outer loops so you never scan forever on malformed input.

Peek asks. Advance commits. You peek to decide; you advance once you have decided. Every off-by-one bug in a hand-written parser is these two getting mixed up.

const peek    = ()  => pos < src.length ? src[pos] : "\0";
const advance = ()  => src[pos++];
const atEnd   = ()  => pos >= src.length;

Character classes

Range comparisons, not regex. They are faster, they are obvious, and they work on a single character where a regex would need a whole engine.

const isDigit = (c) => c >= "0" && c <= "9";
const isAlpha = (c) => (c >= "a" && c <= "z")
                   || (c >= "A" && c <= "Z")
                   ||  c === "_";
const isHex   = (c) => isDigit(c) || (c >= "a" && c <= "f")
                                  || (c >= "A" && c <= "F");
const isSpace = (c) => c === " " || c === "\t";

Derived helpers

Composition of the three primitives. Written once, reused everywhere.

// Consume characters while a predicate holds; return the covered text.
function consumeWhile(pred) {
  const start = pos;
  while (!atEnd() && pred(peek())) advance();
  return src.slice(start, pos);
}

// An unsigned integer.
function readNumber() {
  return Number(consumeWhile(isDigit));
}

// Consume ch only if it is there. Returns whether it was. Never throws.
function match(ch) {
  if (peek() !== ch) return false;
  advance();
  return true;
}

The contract every parse function obeys

RuleMeaning
Enter on the first character When parseX() is called, pos sits on the first character of the X being parsed. It never has to skip in.
Return the value The function returns the structured result — a number, an object, a node — and nothing about position.
Exit on the first character you did not consume On return, pos sits on the next unconsumed character. Not one before, not one after.
Consume nothing on a decision If you peek() to choose a branch, position is unchanged when the branch is taken. The branch does its own consuming.

Hold every function to those four lines and they compose without you having to reason about them together. Break one — a function that leaves pos one past where it should — and every caller above it becomes subtly wrong.

The tmux dimension pair, end to end

// "382x99" → { w: 382, h: 99 }
function parseDims() {
  const w = readNumber();
  match("x");          // Lesson 2 upgrades this to expect("x")
  const h = readNumber();
  return { w, h };
}
